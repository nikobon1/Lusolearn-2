# Изменения структуры базы (Supabase)

Скрипты в `migrations/` запускаются вручную, один раз, по порядку:

1. Откройте Supabase → проект → **SQL Editor** → **New query**.
2. Вставьте содержимое файла и нажмите **Run**.

Скрипты можно безопасно запускать повторно.

| Файл | Что делает |
|---|---|
| `20261125_review_logs.sql` | Журнал повторений `review_logs` (каждая оценка карточки) и поле `profiles.study_plan` (лимиты дневного плана). Нужен для синхронизации прогресса дня между устройствами и в будущем — для алгоритма FSRS. ✅ применён |
| `20261126_video_lessons.sql` | Таблица `video_lessons` — видеоуроки (расшифровка, ссылка, разбор лексики), чтобы они были на всех устройствах. ✅ применён |
| `20261127_word_entries.sql` | Колонка `flashcards.difficulty` (без неё база отклоняла сохранение расписания карточек) и общая база статей слов `word_entries`: читать могут все, писать — только сервер. Наполняется из уже созданных карточек. ✅ применён |
| `20261128_practice_logs.sql` | Журнал тренировок `practice_logs` (каждый ответ во «Фразах-шаблонах» и «Тренажёре спряжений»). Нужен «Занятию на сегодня» и чтобы статистика тренажёров совпадала на всех устройствах. ✅ применён |
| `20261129_stories_v2.sql` | Колонка `stories.data` — истории нового формата: предложения с переводом, словарик, вопросы, номер серии. Без неё сохраняется только текст. ✅ применён |
| `20261130_fsrs.sql` | Колонка `flashcards.fsrs` — состояние памяти по алгоритму FSRS (стабильность и сложность слова). Без неё расписание считается по FSRS, но после перезагрузки оценивается заново по интервалу. ✅ применён |
| `20261201_frequency_progress.sql` | Колонка `profiles.frequency_progress` — отметки «Знаю» в «С нуля» (и результаты проверки словарного запаса) и дневная цель, общие для всех устройств. |

Пока миграция не применена, приложение работает как раньше: прогресс дня, видеоуроки и статистика тренажёров хранятся в браузере.

## Секретный ключ для общей базы слов

Функция `/api/word` записывает новые статьи в `word_entries` ключом **service role**.
Его нужно добавить в Vercel: Settings → Environment Variables → `SUPABASE_SERVICE_ROLE_KEY`
(значение: Supabase → Project Settings → API Keys → `service_role` / secret key).
Ключ даёт полный доступ к базе: только в Vercel, никогда в коде, чатах и браузере.
Без него карточки генерируются как раньше, но в общую базу не сохраняются.
